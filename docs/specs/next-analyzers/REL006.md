# REL006: Evitar dependencias scoped capturadas em hosted services

## Estado planejado

| Campo | Valor |
| ----- | ----- |
| ID | `REL006` |
| Pacote | `Swa.Analyzers.Reliability` |
| Categoria | Reliability |
| Severidade | Warning |
| Estado padrao | Habilitada para tipos conhecidos |
| Code fix | Nao |

## Problema

`BackgroundService` e implementacoes registradas por `AddHostedService` executam como singletons. A documentacao da Microsoft orienta criar escopo para consumir scoped services em `BackgroundService`. `IOptionsSnapshot<T>` tambem e documentado como scoped e indicado para dependencias transient/scoped, enquanto `IOptionsMonitor<T>` e apropriado para singletons.

Fontes principais:

- <https://learn.microsoft.com/en-us/dotnet/core/extensions/scoped-service>
- <https://learn.microsoft.com/en-us/dotnet/core/extensions/options>
- <https://learn.microsoft.com/en-us/ef/core/dbcontext-configuration/>

## Escopo da primeira versao

Detectar tipos hosted service que capturam diretamente dependencias conhecidamente scoped:

- `Microsoft.EntityFrameworkCore.DbContext` e derivados;
- `Microsoft.Extensions.Options.IOptionsSnapshot<T>`;
- tipos configurados por `dotnet_diagnostic.REL006.scoped_type_patterns`.

Nao inferir genericamente lifetimes customizados a partir de `IServiceCollection`, `AddScoped`, `TryAddScoped`, factories ou extensoes de DI.

## Identificacao de hosted service

Um tipo deve ser analisado quando:

- herda direta ou indiretamente de `Microsoft.Extensions.Hosting.BackgroundService`; ou
- implementa direta ou indiretamente `Microsoft.Extensions.Hosting.IHostedService`.

Nao reportar se as referencias de hosting nao estiverem disponiveis.

## Constructor injection

Reportar parametro de construtor cujo tipo seja scoped conhecido/configurado e seja capturado pelo hosted service.

Captura inclui:

- atribuicao direta para field ou propriedade de instancia;
- primary constructor parameter usado em membro de instancia, quando suportado semanticamente pelo Roslyn usado no projeto;
- parametro armazenado em colecao/campo de tipo mais amplo, apenas se a implementacao conseguir identificar com baixo ruido.

Exemplo nao conforme:

```csharp
public sealed class Worker(AppDbContext db) : BackgroundService
{
    protected override Task ExecuteAsync(CancellationToken stoppingToken)
    {
        return db.Orders.CountAsync(stoppingToken);
    }
}
```

Exemplo nao conforme classico:

```csharp
public sealed class Worker : BackgroundService
{
    private readonly AppDbContext _db;

    public Worker(AppDbContext db)
    {
        _db = db;
    }
}
```

## Fields capturados

Reportar fields de instancia cujo tipo seja scoped conhecido/configurado em tipo hosted service, mesmo quando o construtor nao estiver disponivel no mesmo arquivo.

Nao reportar fields `static`, `const` ou fields em tipos que nao sejam hosted services.

## Tipos validos

Nao reportar os tipos abaixo apenas por aparecerem em hosted services:

- `Microsoft.Extensions.DependencyInjection.IServiceScopeFactory`;
- `Microsoft.EntityFrameworkCore.IDbContextFactory<TContext>`;
- `Microsoft.Extensions.Options.IOptionsMonitor<T>`;
- `Microsoft.Extensions.Options.IOptions<T>`;
- `System.IServiceProvider`.

`IServiceProvider` pode indicar Service Locator, mas esta preocupacao pertence a uma regra futura (`ARC008`) e nao a `REL006`.

## Reconhecimento semantico

- `DbContext`: tipo exato ou derivado de `Microsoft.EntityFrameworkCore.DbContext`.
- `IOptionsSnapshot<T>`: `OriginalDefinition` igual a `Microsoft.Extensions.Options.IOptionsSnapshot<T>`.
- Tipos customizados: nome totalmente qualificado do tipo deve casar com algum padrao configurado.

Nao usar apenas nomes simples como `DbContext` ou `IOptionsSnapshot`.

## Configuracao publica planejada

```ini
[*.cs]
dotnet_diagnostic.REL006.scoped_type_patterns = MyApp.*.ScopedServices.*;MyApp.Data.*
```

Sem configuracao, apenas tipos conhecidos sao considerados scoped.

Semantica dos padroes:

- lista separada por `;`;
- espacos ao redor de entradas sao ignorados;
- entrada vazia e ignorada;
- `*` casa zero ou mais caracteres dentro do nome totalmente qualificado;
- comparacao ordinal, case-sensitive.

Comportamento para configuracao invalida:

- se a opcao estiver ausente ou vazia, usar lista vazia;
- entradas invalidas individualmente devem ser ignoradas;
- a regra nao deve emitir diagnostico de configuracao invalida na primeira versao;
- tipos conhecidos continuam ativos mesmo se a configuracao customizada for invalida.

## Falsos positivos a evitar

Nao reportar:

```csharp
public sealed class Worker(IServiceScopeFactory scopeFactory) : BackgroundService
{
}
```

```csharp
public sealed class Worker(IDbContextFactory<AppDbContext> factory) : BackgroundService
{
}
```

```csharp
public sealed class Worker(IOptionsMonitor<MyOptions> options) : BackgroundService
{
}
```

```csharp
public sealed class Worker(IServiceProvider services) : BackgroundService
{
}
```

Nao reportar tipos que apenas recebem scoped service em metodo local depois de criar escopo:

```csharp
await using var scope = scopeFactory.CreateAsyncScope();
var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
```

## Limitacoes conhecidas

- Nao valida se o hosted service foi registrado corretamente no container.
- Nao calcula lifetime de servicos customizados por chamadas `AddScoped`.
- Nao segue factories, delegates ou service locators.
- Nao diferencia todos os casos de primary constructor se a API Roslyn local nao expuser simbolos de forma suficiente; nesse caso, adiar primary constructors e documentar no arquivo de regra final.

## Testes esperados

- Reporta `BackgroundService` com `DbContext` derivado em construtor classico.
- Reporta `IHostedService` direto com `IOptionsSnapshot<T>`.
- Reporta field de `DbContext` em hosted service.
- Reporta primary constructor quando suportado.
- Reporta tipo customizado por `scoped_type_patterns`.
- Nao reporta `IServiceScopeFactory`.
- Nao reporta `IDbContextFactory<TContext>`.
- Nao reporta `IOptionsMonitor<T>`.
- Nao reporta apenas `IServiceProvider`.
- Ignora configuracao customizada invalida sem quebrar tipos conhecidos.
