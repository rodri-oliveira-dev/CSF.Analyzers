# REL005: Evitar operacoes concorrentes no mesmo DbContext

## Estado planejado

| Campo | Valor |
| ----- | ----- |
| ID | `REL005` |
| Pacote | `CSF.Analyzers.Reliability` |
| Categoria | Reliability |
| Severidade | Warning |
| Estado padrao | Habilitada |
| Code fix | Nao |

## Problema

EF Core documenta que uma instancia de `DbContext` nao suporta multiplas operacoes paralelas. Isso inclui consultas async em paralelo e uso concorrente explicito em multiplas threads. A regra deve detectar padroes locais de codigo que iniciam duas ou mais operacoes EF Core sobre a mesma instancia de `DbContext`.

Fonte principal: <https://learn.microsoft.com/en-us/ef/core/dbcontext-configuration/>

## Escopo da primeira versao

Reportar quando houver alta confianca de que duas ou mais operacoes EF Core podem executar ao mesmo tempo usando o mesmo simbolo raiz de `DbContext`.

### Caso 1: `Task.WhenAll` com operacoes inline

```csharp
await Task.WhenAll(
    db.Customers.ToListAsync(),
    db.Orders.ToListAsync());
```

Diagnosticar cada operacao concorrente depois da primeira, ou diagnosticar a chamada `Task.WhenAll` com mensagem contendo o nome da raiz `db`. A implementacao deve escolher uma unica estrategia e mante-la consistente nos testes.

### Caso 2: tarefas iniciadas antes do await

```csharp
var customersTask = db.Customers.ToListAsync();
var ordersTask = db.Orders.ToListAsync();

await Task.WhenAll(customersTask, ordersTask);
```

Diagnosticar quando variaveis locais inicializadas por operacoes EF Core sobre a mesma raiz forem passadas para o mesmo `Task.WhenAll`.

### Caso 3: `Parallel.ForEachAsync`

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await db.Orders
        .Where(x => x.CustomerId == id)
        .ToListAsync(ct);
});
```

Diagnosticar operacao EF Core dentro do delegate quando a raiz `DbContext` e capturada de fora do delegate.

## Identificacao semantica de DbContext

Um tipo deve ser considerado `DbContext` quando:

- e exatamente `Microsoft.EntityFrameworkCore.DbContext`; ou
- herda direta ou indiretamente de `Microsoft.EntityFrameworkCore.DbContext`.

Nao considerar tipos apenas pelo nome `DbContext`. Se a referencia a EF Core nao estiver disponivel na compilacao, a regra nao deve reportar.

## Simbolo raiz

A raiz e o simbolo que representa a instancia de contexto usada para chegar ate a operacao EF:

- parametro: `db.Customers.ToListAsync()` tem raiz `db`;
- variavel local: `context.Set<Order>().ToListAsync()` tem raiz `context`;
- field: `_db.Orders.ToListAsync()` tem raiz `_db`;
- propriedade auto/injetada: `Db.Orders.ToListAsync()` pode ser considerada raiz quando o simbolo da propriedade tem tipo `DbContext`.

Duas operacoes usam a mesma instancia candidata quando o simbolo raiz e igual por `SymbolEqualityComparer.Default`.

Nao tentar provar aliasing complexo nesta primeira versao. Exemplos adiados:

```csharp
var a = db;
var b = db;
await Task.WhenAll(a.Customers.ToListAsync(), b.Orders.ToListAsync());
```

## Operacoes EF no escopo

Reconhecer semanticamente chamadas de `Microsoft.EntityFrameworkCore.EntityFrameworkQueryableExtensions` que executam consulta async, no minimo:

- `ToListAsync`
- `ToArrayAsync`
- `FirstAsync`
- `FirstOrDefaultAsync`
- `SingleAsync`
- `SingleOrDefaultAsync`
- `AnyAsync`
- `AllAsync`
- `CountAsync`
- `LongCountAsync`
- `SumAsync`
- `AverageAsync`
- `MinAsync`
- `MaxAsync`
- `ForEachAsync`
- `LoadAsync`, quando disponivel via EF Core extensions

Tambem reconhecer operacoes de escrita em `DbContext`:

- `SaveChangesAsync`

`SaveChanges` sincrono, `ToList` sincrono e outros bloqueios sincronizados ficam fora da primeira versao, exceto se estiverem dentro de `Parallel.ForEachAsync`; mesmo nesse caso, incluir apenas se a implementacao conseguir baixo ruido.

## Padroes de concorrencia incluidos

- `System.Threading.Tasks.Task.WhenAll(...)`.
- `Task.WhenAll(IEnumerable<Task>)` apenas quando a colecao for array ou collection expression local com operacoes/variaveis rastreaveis no mesmo metodo.
- `System.Threading.Tasks.Parallel.ForEachAsync(...)` com lambda ou anonymous function local.

Fora da primeira versao:

- `Task.Run`, `Thread`, `Parallel.For`, `Parallel.ForEach` sincrono, TPL Dataflow, Channels, timers e filas customizadas.
- `Task.WhenAny`, porque concorrencia existe mas a intencao de cancelamento/competicao exige heuristicas diferentes.
- Analise interprocedural de metodos que retornam `Task` iniciada com `DbContext`.

## Fields, parametros e variaveis locais

- Parametros, locals e fields podem ser diagnosticados se o simbolo raiz for semanticamente identificado.
- Para fields, a regra deve reportar apenas quando as operacoes aparecem no mesmo metodo/delegate analisado.
- Para variaveis locais que armazenam tarefas, rastrear somente declaracoes locais no mesmo bloco ou bloco pai simples antes do `Task.WhenAll`.
- Nao rastrear atribuicoes condicionais, reatribuicoes, loops complexos ou variaveis capturadas por delegates diferentes.

## Dois DbContexts distintos

Nao reportar quando as raizes forem simbolos diferentes:

```csharp
await Task.WhenAll(
    salesDb.Customers.ToListAsync(),
    billingDb.Invoices.ToListAsync());
```

Tambem nao reportar quando cada operacao usa uma instancia criada separadamente por factory:

```csharp
await Task.WhenAll(
    QueryCustomersAsync(factory),
    QueryOrdersAsync(factory));
```

Esse exemplo depende de metodos auxiliares e fica fora do escopo; a regra simplesmente nao deve inferir problema sem operacoes EF locais na mesma raiz.

## `IDbContextFactory<TContext>`

`IDbContextFactory<TContext>` deve ser tratado como alternativa valida quando cada fluxo cria seu proprio contexto:

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await using var db = await factory.CreateDbContextAsync(ct);
    await db.Orders.Where(x => x.CustomerId == id).ToListAsync(ct);
});
```

Nao reportar captura de `IDbContextFactory<TContext>`. Reportar apenas se uma instancia de `DbContext` criada fora do padrao concorrente for compartilhada entre operacoes concorrentes.

## Casos que nao devem gerar diagnostico

```csharp
var customers = await db.Customers.ToListAsync();
var orders = await db.Orders.ToListAsync();
```

```csharp
await Task.WhenAll(
    salesDb.Customers.ToListAsync(),
    billingDb.Orders.ToListAsync());
```

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await using var db = await factory.CreateDbContextAsync(ct);
    await db.Orders.Where(x => x.CustomerId == id).ToListAsync(ct);
});
```

```csharp
var query = db.Orders.Where(x => x.IsOpen);
var result = await query.ToListAsync();
```

## Limitacoes conhecidas

- Sem analise interprocedural.
- Sem prova completa de aliasing.
- Sem analise de lifetime DI.
- Sem deteccao de concorrencia criada por bibliotecas customizadas.
- Sem garantia de identificar todos os metodos EF Core que executam consulta na primeira versao.

## Testes esperados

- Reporta `Task.WhenAll` inline com mesma raiz.
- Reporta tarefas locais iniciadas antes do `await`.
- Reporta `Parallel.ForEachAsync` capturando contexto externo.
- Nao reporta awaits sequenciais.
- Nao reporta dois simbolos raiz diferentes.
- Nao reporta `IDbContextFactory<TContext>` criando contexto dentro do delegate.
- Nao reporta metodos homonimos sem simbolos EF Core.
- Nao reporta quando EF Core nao esta referenciado.
