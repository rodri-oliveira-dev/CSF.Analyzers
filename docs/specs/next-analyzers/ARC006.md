# ARC006: Evitar entidades de dominio diretamente em contratos HTTP

## Estado planejado

| Campo | Valor |
| ----- | ----- |
| ID | `ARC006` |
| Pacote | `CSF.Analyzers.Architecture` |
| Categoria | Architecture |
| Severidade | Info |
| Estado padrao | Opt-in |
| Code fix | Nao |

## Problema

Projetos que adotam DDD frequentemente separam entidades de dominio de contratos HTTP. Expor entidades diretamente em actions ou Minimal APIs acopla contrato externo ao modelo de dominio, dificulta versionamento e pode vazar estado/invariantes.

`ARC006` e uma politica arquitetural opt-in. Ela nao afirma que retornar entidades e sempre incorreto em todo projeto ASP.NET Core.

Fontes ASP.NET Core:

- <https://learn.microsoft.com/en-us/aspnet/core/web-api/action-return-types>
- <https://learn.microsoft.com/en-us/aspnet/core/fundamentals/minimal-apis/responses>

## Relacao com ARC004

A regra deve reutilizar, sempre que tecnicamente adequado, a identificacao de entidade de [ARC004](../../rules/architecture/ARC004.md):

- marcadores padrao de namespace: `.Domain.Entities`, `.Domain.Entity`, `.Domain.Aggregates`, `.Domain.Aggregate`;
- nomes padrao de base/interface: `Entity`, `AggregateRoot`, `IEntity`, `IAggregateRoot`;
- opcoes publicas de namespaces e tipos base.

Antes de implementar `ARC006`, preferir extrair a logica de `ARC004` para helper interno do pacote Architecture, por exemplo `DomainEntityClassifier`, para evitar duas definicoes de entidade.

## Configuracao planejada

Preferir reutilizar opcoes de `ARC004`:

```ini
[*.cs]
dotnet_diagnostic.ARC006.severity = info
dotnet_diagnostic.ARC004.entity_namespaces = ["MyApp.Domain.Entities", "MyApp.Domain.Aggregates"]
dotnet_diagnostic.ARC004.entity_base_types = ["Entity", "AggregateRoot"]
```

Se a implementacao concluir que compartilhar chaves com `ARC004` gera acoplamento ruim, criar aliases equivalentes para `ARC006`, mas manter a mesma semantica e documentar a decisao. A preferencia desta SDD e nao duplicar opcoes.

## MVC controllers e actions

Analisar metodos que sejam actions MVC por sinais semanticos ja usados em `ARC001`/`ARC003` quando aplicavel:

- tipo contendo herda de `Microsoft.AspNetCore.Mvc.ControllerBase` ou `Controller`;
- metodo tem atributo HTTP conhecido (`HttpGetAttribute`, `HttpPostAttribute`, `HttpPutAttribute`, `HttpPatchAttribute`, `HttpDeleteAttribute`) ou atributo de rota em controller/action com padrao de action publica.

### Parametros

Reportar parametro de action cujo tipo desembrulhado seja entidade:

```csharp
[HttpPost]
public IActionResult Create(Order order)
```

Nao reportar parametros de infraestrutura ASP.NET, por exemplo `CancellationToken`, `HttpContext`, `ClaimsPrincipal`, `IFormFile`.

### Retornos

Reportar retorno de action cujo tipo desembrulhado seja entidade:

```csharp
[HttpGet("{id}")]
public Task<Order> Get(Guid id)
```

Exemplo conforme:

```csharp
[HttpGet("{id}")]
public Task<OrderResponse> Get(Guid id)
```

## Minimal APIs

Analisar handlers passados para mapeamentos HTTP quando o tipo do delegate puder ser determinado semanticamente.

Mapeamentos no escopo inicial:

- `MapGet`
- `MapPost`
- `MapPut`
- `MapPatch`
- `MapDelete`

Reportar:

- parametro de handler Minimal API cujo tipo desembrulhado seja entidade e nao seja conhecido como servico/infrastrutura;
- retorno inferido ou declarado cujo tipo desembrulhado contenha entidade.

Nao reportar quando a inferencia semantica do retorno nao estiver disponivel de forma confiavel.

## Wrappers e desembrulho de tipos

Desembrulhar recursivamente os seguintes wrappers conhecidos:

- `System.Threading.Tasks.Task<T>`;
- `System.Threading.Tasks.ValueTask<T>`;
- `Microsoft.AspNetCore.Mvc.ActionResult<T>`;
- colecoes conhecidas: `IEnumerable<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `ICollection<T>`, `IList<T>`, `List<T>`, arrays;
- typed results ASP.NET Core: `Microsoft.AspNetCore.Http.HttpResults.Ok<T>`, `Created<T>`, `CreatedAtRoute<T>`, `CreatedAtAction<T>`;
- union typed results: `Microsoft.AspNetCore.Http.HttpResults.Results<T1,...>` ou equivalente disponivel na versao referenciada.

`IActionResult`, `ActionResult` nao generico e `IResult` sem tipo generico nao devem gerar diagnostico, porque o payload nao e conhecido estaticamente.

## Resultados mistos

Reportar quando qualquer alternativa generica de `Results<...>` ou typed result contiver entidade:

```csharp
Results<Ok<Order>, NotFound> Get(Guid id)
```

Nao reportar alternativas sem payload, como `NotFound`, `NoContent` ou `BadRequest` sem tipo generico.

## DTOs e analise profunda

Nao fazer analise profunda arbitraria de propriedades internas de DTOs na primeira versao.

Nao reportar:

```csharp
public sealed class OrderResponse
{
    public Guid Id { get; init; }
}
```

Mesmo que um DTO contenha uma propriedade de entidade, adiar essa heuristica:

```csharp
public sealed class OrderResponse
{
    public Order Inner { get; init; } = null!;
}
```

Motivo: isso aumenta ruido em modelos de composicao, wrappers internos e casos de serializacao controlada.

## Casos que nao devem gerar diagnostico

- Tipos fora do contexto HTTP.
- Actions que retornam DTOs, primitives, records de contrato ou anonymous objects.
- `IActionResult`, `ActionResult` ou `IResult` sem payload generico.
- Entidades usadas internamente dentro do corpo da action mas mapeadas para DTO antes do retorno.
- Parametros injetados em Minimal APIs por DI quando nao sao body-bound e a inferencia for ambigua.

## Limitacoes conhecidas

- Sem analise de serializacao profunda.
- Sem analise interprocedural de metodos auxiliares que criam responses.
- Sem inferir payload de `Results.Ok(object)` quando o argumento e `object`, `dynamic` ou outro tipo apagado.
- Minimal APIs com delegates construidos dinamicamente podem ficar fora do escopo.

## Testes esperados

- Reporta parametro MVC de entidade.
- Reporta retorno MVC `Order`, `Task<Order>`, `ActionResult<Order>` e `Task<ActionResult<Order>>`.
- Reporta colecao de entidade.
- Reporta Minimal API retornando entidade por lambda.
- Reporta `Results<Ok<Order>, NotFound>`.
- Nao reporta DTO com nome parecido.
- Nao reporta tipo fora de action/handler HTTP.
- Nao reporta `IActionResult` sem payload generico.
- Reutiliza configuracao de entidade de `ARC004`.
