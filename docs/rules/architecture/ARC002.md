# ARC002: Evitar dependências de infraestrutura em camadas de domínio/aplicação

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Architecture` |
| Categoria | Architecture |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Detectar referências diretas a namespaces de infraestrutura dentro de namespaces configurados como camadas core.

## Motivação

Domínio e aplicação devem depender de abstrações próprias. Referências diretas a EF Core, ASP.NET Core, Redis ou providers concretos acoplam regras de negócio a detalhes externos.

## Código não conforme

```csharp
using Microsoft.EntityFrameworkCore;

namespace Billing.Domain;

public sealed class Invoice
{
    private readonly DbContext _dbContext;
}
```

## Código conforme

```csharp
namespace Billing.Application;

public interface IInvoiceReadStore
{
    Task<Invoice?> FindAsync(Guid id, CancellationToken cancellationToken);
}
```

## Heurística

A regra compara o namespace do arquivo/símbolo analisado com padrões core e reporta usos de símbolos cujo namespace corresponde aos padrões proibidos, salvo quando também corresponde a padrões permitidos. Projetos ou namespaces de teste são ignorados quando `ignore_tests` está ativo.

## Opções públicas

```ini
[*.cs]
dotnet_diagnostic.ARC002.core_namespace_patterns = "*.Domain;*.Application"
dotnet_diagnostic.ARC002.forbidden_namespace_patterns = "Microsoft.EntityFrameworkCore;Microsoft.AspNetCore;StackExchange.Redis;Npgsql"
dotnet_diagnostic.ARC002.allowed_namespace_patterns =
dotnet_diagnostic.ARC002.ignore_tests = true
```

- `core_namespace_patterns`: lista separada por `;` de namespaces core.
- `forbidden_namespace_patterns`: lista separada por `;` de namespaces proibidos.
- `allowed_namespace_patterns`: lista separada por `;` de exceções.
- `ignore_tests`: booleano.

## Fallback de configuração

Valores ausentes usam defaults internos. Padrões vazios, duplicados ou com mais de 256 caracteres são ignorados; a lista é limitada a 128 padrões. `ignore_tests` inválido volta para `true`.

## Limitações

A regra não prova arquitetura correta; ela aplica uma política por namespace. Configure os padrões antes de usar como bloqueio.

## Impacto esperado

Ajuda a manter separação entre core e infraestrutura em soluções com camadas claras.

## Suppression

Suprima localmente quando uma exceção é parte consciente da arquitetura, ou use `allowed_namespace_patterns` para exceções recorrentes.

## Relação com ferramentas externas

Ferramentas de arquitetura podem oferecer verificações semelhantes em outro nível. `ARC002` mantém a política próxima do compilador e configurável por `.editorconfig`.
