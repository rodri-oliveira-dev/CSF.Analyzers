# ARC001: Exigir autorização explícita em endpoints HTTP

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Architecture` |
| Categoria | Security |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Garantir que endpoints HTTP declarem uma decisão explícita: protegidos por `[Authorize]`/`RequireAuthorization()` ou públicos por `[AllowAnonymous]`/`AllowAnonymous()`.

## Motivação

Endpoints sem metadado de autorização podem surgir por esquecimento. A regra torna a decisão revisável no código.

## Código não conforme

```csharp
[HttpGet("orders")]
public IActionResult Get() => Ok();

app.MapGet("/orders", () => Results.Ok());
```

## Código conforme

```csharp
[Authorize]
public sealed class OrdersController : ControllerBase
{
    [HttpGet("orders")]
    public IActionResult Get() => Ok();
}

app.MapGet("/orders", () => Results.Ok())
    .RequireAuthorization();
```

## Heurística

A regra reconhece controllers ASP.NET, atributos HTTP MVC/Web API e Minimal APIs `MapGet`, `MapPost`, `MapPut`, `MapPatch`, `MapDelete` e `MapMethods`. Ela aceita decisões no método, tipo, hierarquia de tipo, cadeia externa do endpoint ou receiver já configurado.

## Opções públicas

```ini
[*.cs]
dotnet_diagnostic.ARC001.allowed_routes = ["/internal/status", "/diagnostics/*"]
dotnet_diagnostic.ARC001.allowed_methods = ["Ping"]
dotnet_diagnostic.ARC001.ignored_namespaces = ["Sample.PublicEndpoints"]
```

- `allowed_routes`: array JSON de rotas liberadas. Há segmentos técnicos padrão como `health`, `healthz`, `swagger`, `metrics`, `ready`, `readiness`, `live` e `liveness`.
- `allowed_methods`: array JSON de nomes de métodos liberados.
- `ignored_namespaces`: array JSON de namespaces ignorados, incluindo subnamespaces.

## Fallback de configuração

Arrays JSON ausentes ou inválidos usam a lista padrão da regra. Valores vazios são descartados. Sem configuração de severidade, a regra fica habilitada como `warning`.

## Limitações

Rotas dinâmicas e padrões customizados fora das APIs ASP.NET reconhecidas podem não ser diagnosticados. A regra não avalia política de autorização efetiva em runtime.

## Impacto esperado

Reduz endpoints acidentalmente públicos e melhora revisão de segurança.

## Suppression

Prefira `AllowAnonymous()` ou allowlist por rota/método. Use suppression local somente para casos que não conseguem expressar a decisão com metadados ASP.NET.

## Relação com ferramentas externas

Nenhum substituto externo direto foi confirmado para exigir decisão explícita por endpoint.
