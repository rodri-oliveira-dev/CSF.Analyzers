# ARC006: Evitar entidades de domínio diretamente em contratos HTTP

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Architecture` |
| Categoria | Architecture |
| Severidade | Info |
| Estado padrão | Opt-in |

## Objetivo

Detectar entidades de domínio expostas diretamente em contratos HTTP de controllers MVC/Web API e Minimal APIs quando o projeto adota separação entre modelo de domínio e contratos externos.

## Motivação

Expor entidades diretamente acopla o contrato público ao domínio, dificulta versionamento, aumenta risco de over-posting em entradas e pode serializar estado ou invariantes que deveriam permanecer internos. Esta regra é opt-in porque essa separação é uma política arquitetural, não uma exigência universal para toda API ASP.NET Core.

## Código não conforme

```csharp
using Microsoft.AspNetCore.Mvc;
using MyApp.Domain.Entities;

public sealed class OrdersController : ControllerBase
{
    [HttpPost("orders")]
    public IActionResult Create(Order order) => Ok();

    [HttpGet("orders/{id}")]
    public Task<Order> Get(Guid id) => GetOrderAsync(id);
}

app.MapPost("/orders", (Order order) => Results.Ok());
```

## Código conforme

```csharp
using Microsoft.AspNetCore.Mvc;

public sealed class OrdersController : ControllerBase
{
    [HttpPost("orders")]
    public IActionResult Create(CreateOrderRequest request) => Ok();

    [HttpGet("orders/{id}")]
    public Task<OrderResponse> Get(Guid id) => GetOrderResponseAsync(id);
}

app.MapPost("/orders", (CreateOrderRequest request) => Results.Ok());
```

## Heurística

A regra analisa assinaturas de actions em controllers ASP.NET Core e handlers passados diretamente para `MapGet`, `MapPost`, `MapPut`, `MapPatch` e `MapDelete`. Ela reporta parâmetros e retornos cujo tipo, após desembrulhar wrappers conhecidos, seja identificado como entidade de domínio pela mesma política usada por `ARC004`.

Wrappers reconhecidos:

- `Task<T>` e `ValueTask<T>`;
- `ActionResult<T>`;
- arrays;
- `IEnumerable<T>`, `IReadOnlyCollection<T>`, `IReadOnlyList<T>`, `ICollection<T>`, `IList<T>` e `List<T>`;
- `Ok<T>`, `Created<T>`, `CreatedAtAction<T>` e `CreatedAtRoute<T>`;
- `Results<T1, ...>` quando qualquer alternativa contém entidade.

`IActionResult`, `ActionResult` não genérico e `IResult` sem payload genérico não geram diagnóstico porque o payload não é conhecido estaticamente.

## Configuração

Ative a regra por `.editorconfig`:

```ini
[*.cs]
dotnet_diagnostic.ARC006.severity = info
```

A identificação de entidades reutiliza as opções públicas de `ARC004`:

```ini
[*.cs]
dotnet_diagnostic.ARC004.entity_namespaces = ["MyApp.Domain.Entities", "MyApp.Domain.Aggregates"]
dotnet_diagnostic.ARC004.entity_base_types = ["Entity", "AggregateRoot"]
```

Além das opções configuradas, a política reconhece namespaces com marcadores `Domain.Entities`, `Domain.Entity`, `Domain.Aggregates` e `Domain.Aggregate`, além dos tipos base ou interfaces `Entity`, `AggregateRoot`, `IEntity` e `IAggregateRoot`.

## Fallback de configuração

Arrays ausentes, vazios ou inválidos em `ARC004.entity_namespaces` e `ARC004.entity_base_types` usam lista configurada vazia, preservando os marcadores e tipos padrão internos. `ARC006` não define aliases próprios para essas opções para evitar duas políticas divergentes de identificação de entidade.

## Limitações

A regra não faz análise profunda de propriedades internas de DTOs, não infere payloads apagados como `object` ou `dynamic`, não executa análise interprocedural arbitrária para descobrir o tipo real retornado por métodos auxiliares e pode ignorar handlers Minimal API construídos dinamicamente. Parâmetros marcados como serviços, como `[FromServices]`, são ignorados.

## Impacto esperado

Ajuda times que adotam DDD a manter contratos HTTP versionáveis, explícitos e desacoplados do modelo de domínio, reduzindo exposição acidental de estado interno.

## Suppression

Use suppression local quando a exposição direta da entidade for uma decisão consciente de contrato. Para padrões recorrentes, ajuste a configuração de identificação de entidades em `ARC004`.

## Relação com ferramentas externas

Analyzers ASP.NET Core ajudam com binding, tipos de retorno e uso de APIs HTTP, mas não substituem esta política DDD. Ferramentas de arquitetura como NDepend ou ArchUnitNET podem validar dependências entre camadas; `ARC006` mantém o feedback no editor/build e combina contexto HTTP com o classificador de entidades compartilhado com `ARC004`.
