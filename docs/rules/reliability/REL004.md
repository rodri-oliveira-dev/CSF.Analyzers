# REL004: Evitar materialização antes de filtro ou projeção

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Reliability` |
| Categoria | Performance |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Evitar materialização de consultas EF Core antes de operadores que poderiam compor a consulta no banco.

## Motivação

`ToList()`, `ToArray()` e `ToListAsync()` encerram a composição. Se `Where`, `Select`, `Skip`, `Take` ou ordenação aparecem depois, o trabalho acontece em memória.

## Código não conforme

```csharp
return _db.Orders
    .ToList()
    .Where(order => order.IsOpen);

var orders = await _db.Orders.ToListAsync();
return orders.Where(order => order.IsOpen);
```

## Código conforme

```csharp
return _db.Orders
    .Where(order => order.IsOpen)
    .ToList();
```

## Heurística

A regra reconhece consultas iniciadas em `DbSet<T>`, materialização síncrona por `ToList`/`ToArray` antes de operadores LINQ seguros, e `ToListAsync` imediatamente seguido por operador em memória na próxima instrução.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Use apenas `dotnet_diagnostic.REL004.severity`. Sem configuração, a regra fica habilitada como `warning`.

## Limitações

Ordenações com comparer explícito não são reportadas. A regra não rastreia fluxos longos entre variáveis e métodos.

## Impacto esperado

Reduz transferência de dados e processamento em memória ao manter filtros, projeções e paginação no banco.

## Suppression

Suprima quando a materialização antes do operador é intencional, por exemplo para usar lógica que não pode ser traduzida pelo provider.

## Relação com ferramentas externas

Analyzers LINQ podem complementar, mas `REL004` diferencia origem EF Core e materializadores relevantes.
