# REL005: Evitar operações concorrentes no mesmo DbContext

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Reliability` |
| Categoria | Reliability |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Evitar duas ou mais operações EF Core potencialmente concorrentes sobre a mesma instância de `DbContext`.

## Motivação

`DbContext` não suporta múltiplas operações paralelas na mesma instância. Consultas async iniciadas em paralelo ou uso de um contexto capturado em `Parallel.ForEachAsync` podem falhar em runtime ou misturar estados internos do contexto.

## Código não conforme

```csharp
await Task.WhenAll(
    db.Customers.ToListAsync(),
    db.Orders.ToListAsync());
```

```csharp
var customersTask = db.Customers.ToListAsync();
var ordersTask = db.Orders.ToListAsync();

await Task.WhenAll(customersTask, ordersTask);
```

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await db.Orders
        .Where(order => order.CustomerId == id)
        .ToListAsync(ct);
});
```

## Código conforme

```csharp
var customers = await db.Customers.ToListAsync();
var orders = await db.Orders.ToListAsync();
```

```csharp
await Task.WhenAll(
    firstDb.Customers.ToListAsync(),
    secondDb.Orders.ToListAsync());
```

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await using var db = await factory.CreateDbContextAsync(ct);
    await db.Orders
        .Where(order => order.CustomerId == id)
        .ToListAsync(ct);
});
```

## Heurística

A regra usa análise semântica e só reporta quando a raiz da operação é um parâmetro, variável local, field ou propriedade cujo tipo é `Microsoft.EntityFrameworkCore.DbContext` ou herda dele.

Os padroes cobertos sao:

- `Task.WhenAll(...)` com operacoes EF Core inline na mesma raiz.
- `Task.WhenAll(...)` com variaveis locais inicializadas por operacoes EF Core no mesmo bloco ou bloco pai simples.
- `Task.WhenAll(IEnumerable<Task>)` quando a colecao local e um array ou collection expression rastreavel.
- `Parallel.ForEachAsync(...)` quando o delegate captura uma instancia externa de `DbContext`.

Operações EF Core reconhecidas incluem materializadores async de `EntityFrameworkQueryableExtensions`, como `ToListAsync`, `FirstAsync`, `AnyAsync`, agregações async e `ForEachAsync`, além de `SaveChangesAsync` em `DbContext`.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Use apenas `dotnet_diagnostic.REL005.severity`. Sem configuração, a regra fica habilitada como `warning`.

## Limitacoes

A regra não faz análise interprocedural, não prova aliasing complexo e não tenta inferir concorrência criada por `Task.Run`, `Task.WhenAny`, threads, filas ou bibliotecas customizadas. Aliases locais como `var a = db; var b = db;` ficam fora da primeira versão.

Código de teste reconhecido por atributos conhecidos é ignorado para reduzir ruído em cenários de seed ou fixtures.

## Impacto esperado

Reduz falhas de runtime e comportamento indefinido causado por uso paralelo de uma instância EF Core que deveria ser usada sequencialmente ou substituída por contextos separados.

## Suppression

Suprima apenas quando houver garantia externa de que as operações não podem executar em paralelo ou quando o código faz parte de um teste que não foi reconhecido automaticamente.

## Relação com ferramentas externas

Analyzers genéricos de async podem complementar a cobertura, mas `REL005` diferencia operações EF Core semanticamente resolvidas e a mesma raiz de `DbContext`.
