# REL005: Evitar operacoes concorrentes no mesmo DbContext

| Campo | Valor |
| ----- | ----- |
| Pacote | `Swa.Analyzers.Reliability` |
| Categoria | Reliability |
| Severidade | Warning |
| Estado padrao | Habilitada |

## Objetivo

Evitar duas ou mais operacoes EF Core potencialmente concorrentes sobre a mesma instancia de `DbContext`.

## Motivacao

`DbContext` nao suporta multiplas operacoes paralelas na mesma instancia. Consultas async iniciadas em paralelo ou uso de um contexto capturado em `Parallel.ForEachAsync` podem falhar em runtime ou misturar estados internos do contexto.

## Codigo nao conforme

```csharp
await Task.WhenAll(
    db.Customers.ToListAsync(),
    db.Orders.ToListAsync());
```

```csharp
var customersTask = db.Customers.ToListAsync();
var ordersTask = db.Orders.ToListAsync();

await Task.WhenAll(customersTask, ordersTask);
```

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await db.Orders
        .Where(order => order.CustomerId == id)
        .ToListAsync(ct);
});
```

## Codigo conforme

```csharp
var customers = await db.Customers.ToListAsync();
var orders = await db.Orders.ToListAsync();
```

```csharp
await Task.WhenAll(
    firstDb.Customers.ToListAsync(),
    secondDb.Orders.ToListAsync());
```

```csharp
await Parallel.ForEachAsync(ids, async (id, ct) =>
{
    await using var db = await factory.CreateDbContextAsync(ct);
    await db.Orders
        .Where(order => order.CustomerId == id)
        .ToListAsync(ct);
});
```

## Heuristica

A regra usa analise semantica e so reporta quando a raiz da operacao e um parametro, variavel local, field ou propriedade cujo tipo e `Microsoft.EntityFrameworkCore.DbContext` ou herda dele.

Os padroes cobertos sao:

- `Task.WhenAll(...)` com operacoes EF Core inline na mesma raiz.
- `Task.WhenAll(...)` com variaveis locais inicializadas por operacoes EF Core no mesmo bloco ou bloco pai simples.
- `Task.WhenAll(IEnumerable<Task>)` quando a colecao local e um array ou collection expression rastreavel.
- `Parallel.ForEachAsync(...)` quando o delegate captura uma instancia externa de `DbContext`.

Operacoes EF Core reconhecidas incluem materializadores async de `EntityFrameworkQueryableExtensions`, como `ToListAsync`, `FirstAsync`, `AnyAsync`, agregacoes async e `ForEachAsync`, alem de `SaveChangesAsync` em `DbContext`.

## Opcoes publicas

Nao ha opcoes publicas especificas.

## Fallback de configuracao

Use apenas `dotnet_diagnostic.REL005.severity`. Sem configuracao, a regra fica habilitada como `warning`.

## Limitacoes

A regra nao faz analise interprocedural, nao prova aliasing complexo e nao tenta inferir concorrencia criada por `Task.Run`, `Task.WhenAny`, threads, filas ou bibliotecas customizadas. Aliases locais como `var a = db; var b = db;` ficam fora da primeira versao.

Codigo de teste reconhecido por atributos conhecidos e ignorado para reduzir ruido em cenarios de seed ou fixtures.

## Impacto esperado

Reduz falhas de runtime e comportamento indefinido causado por uso paralelo de uma instancia EF Core que deveria ser usada sequencialmente ou substituida por contextos separados.

## Suppression

Suprima apenas quando houver garantia externa de que as operacoes nao podem executar em paralelo ou quando o codigo faz parte de um teste que nao foi reconhecido automaticamente.

## Relacao com ferramentas externas

Analyzers genericos de async podem complementar a cobertura, mas `REL005` diferencia operacoes EF Core semanticamente resolvidas e a mesma raiz de `DbContext`.
