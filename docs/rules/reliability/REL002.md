# REL002: Evitar fire-and-forget em fluxo de request

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Reliability` |
| Categoria | Reliability |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Detectar descarte explícito de `Task` ou `ValueTask` dentro de fluxos de request ASP.NET.

## Motivação

Fire-and-forget em endpoints pode perder exceções, ignorar cancelamento e deixar trabalho rodando depois do fim do request.

## Código não conforme

```csharp
public sealed class OrdersController : ControllerBase
{
    public void Post()
    {
        _ = SaveAsync();
    }
}

app.MapPost("/orders", () =>
{
    _ = PublishAsync();
});
```

## Código conforme

```csharp
public sealed class OrdersController : ControllerBase
{
    public Task Post()
    {
        return SaveAsync();
    }
}
```

## Heurística

A regra analisa assignments para descarte e expression statements que descartam tarefas em controllers, actions HTTP e handlers inline de Minimal APIs. Hosted services e testes reconhecidos são ignorados. `Task.Run(...)` no mesmo contexto também pode ser reportado.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Use apenas `dotnet_diagnostic.REL002.severity`. Sem configuração, a regra fica habilitada como `warning`.

## Limitações

O analyzer não modela todos os fluxos de dados possíveis. Ele mira descartes locais claros de `Task` e `ValueTask`.

## Impacto esperado

Torna trabalho assíncrono observável e reduz falhas silenciosas em produção.

## Suppression

Suprima apenas quando houver infraestrutura explícita para observar exceções e ciclo de vida da tarefa, preferindo encapsular o caso em fila ou hosted service.

## Relação com ferramentas externas

Regras externas de tarefas não observadas podem complementar a cobertura. `REL002` é específica para request ASP.NET.
