# REL003: Preferir AsNoTracking em consultas somente leitura

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Reliability` |
| Categoria | Performance |
| Severidade | Info |
| Estado padrão | Opt-in |

## Objetivo

Sugerir `AsNoTracking()` em consultas EF Core materializadas para leitura quando não há evidência de alteração e persistência da entidade no mesmo método.

## Motivação

O tracking do EF Core custa memória e CPU. Em consultas somente leitura, `AsNoTracking()` reduz custo e torna a intenção explícita.

## Código não conforme

```csharp
return await _db.Orders
    .Where(order => order.IsOpen)
    .ToListAsync();
```

## Código conforme

```csharp
return await _db.Orders
    .AsNoTracking()
    .Where(order => order.IsOpen)
    .ToListAsync();
```

## Heurística

A regra reconhece cadeias iniciadas em `DbSet<T>` e materializadas por métodos EF Core ou LINQ conhecidos. Ela não reporta quando já existe decisão explícita de tracking, quando há configuração global `NoTracking`, ou quando o método altera entidade e chama `SaveChanges`/`SaveChangesAsync`.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Sem configuração, a regra fica desabilitada. Ative com:

```ini
[*.cs]
dotnet_diagnostic.REL003.severity = info
```

## Limitações

A regra usa heurística conservadora. Ela pode não inferir intenções que atravessam métodos, helpers ou repositórios complexos.

## Impacto esperado

Melhora performance de consultas de leitura em projetos EF Core que adotam tracking explícito.

## Suppression

Suprima quando a consulta precisa retornar entidades rastreadas por contrato ou por fluxo de escrita indireto que a heurística não consegue perceber.

## Relação com ferramentas externas

Nenhum substituto externo direto foi confirmado para esta heurística contextual.
