# REL001: Evitar Task.Run em fluxo de request ASP.NET

| Campo | Valor |
| ----- | ----- |
| Pacote | `Swa.Analyzers.Reliability` |
| Categoria | Performance |
| Severidade | Warning |
| Estado padrão | Habilitada |

## Objetivo

Detectar `Task.Run` e `Task.Factory.StartNew` usados dentro de fluxos de request ASP.NET.

## Motivação

Em um request ASP.NET, mover trabalho para outro thread do ThreadPool normalmente não melhora escalabilidade e pode esconder a necessidade de APIs assíncronas reais ou processamento em background.

## Código não conforme

```csharp
public sealed class OrdersController : ControllerBase
{
    public async Task<int> Get()
    {
        return await Task.Run(() => LoadOrder());
    }
}

app.MapPost("/orders", () =>
{
    _ = Task.Run(() => SaveOrder());
});
```

## Código conforme

```csharp
public sealed class OrdersController : ControllerBase
{
    public Task<int> Get(CancellationToken cancellationToken)
    {
        return LoadOrderAsync(cancellationToken);
    }
}
```

## Heurística

A regra reconhece controllers ASP.NET, actions com atributos HTTP e handlers inline de Minimal APIs. Ela reporta `Task.Run` e `Task.Factory.StartNew`. Testes reconhecidos e tipos derivados de `BackgroundService` ou que implementam `IHostedService` são ignorados.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Use apenas `dotnet_diagnostic.REL001.severity`. Sem configuração, a regra fica habilitada como `warning`.

## Limitações

O analyzer depende de símbolos de ASP.NET e `System.Threading.Tasks`. Handlers dinâmicos ou abstrações customizadas fora dos padrões reconhecidos podem não ser diagnosticados.

## Impacto esperado

Reduz consumo desnecessário do ThreadPool no caminho de request e incentiva APIs assíncronas reais ou filas explícitas.

## Suppression

Suprima localmente apenas quando o código está em um adaptador legado e a migração para API assíncrona ou background service já foi avaliada.

## Relação com ferramentas externas

Analyzers gerais de async podem apontar problemas relacionados. `REL001` permanece mais contextual por restringir o alerta ao fluxo de request ASP.NET.
