# TST001: Restrict permissive NSubstitute argument matching

| Campo | Valor |
| ----- | ----- |
| Pacote | `Swa.Analyzers.Testing` |
| Categoria | TestQuality |
| Severidade | Info |
| Estado padrao | Opt-in |

## Objetivo

Evitar matchers e APIs excessivamente permissivas do NSubstitute quando elas reduzem a precisao do teste.

## Motivacao

`Arg.Any<T>()` e as APIs `*AnyArgs` ignoram valores de argumentos. Em expectativas positivas e setups, isso pode esconder valores importantes e tornar o teste menos especifico.

Verificacoes negativas amplas continuam aceitas quando a intencao e confirmar ausencia de chamada independentemente dos argumentos.

## Codigo nao conforme

```csharp
sender.Send(Arg.Any<string>());
sender.Received().Send(Arg.Any<string>());
sender.ReceivedWithAnyArgs().Send(default!);

formatter.Format("hello").ReturnsForAnyArgs("formatted");
sender.WhenForAnyArgs(x => x.Send(default!)).Do(_ => { });
```

## Codigo conforme

```csharp
sender.Send("hello");
sender.Received().Send("hello");

sender.DidNotReceive().Send(Arg.Any<string>());
sender.DidNotReceiveWithAnyArgs().Send(Arg.Any<string>());
sender.DidNotReceiveWithAnyArgs().Send(default!);
```

## Heuristica

A regra so roda quando encontra contexto de teste reconhecido por atributos conhecidos e referencia a `NSubstitute.Arg`.

Ela reporta semanticamente:

- `NSubstitute.Arg.Any<T>()` fora de argumento direto em cadeia `DidNotReceive()` ou `DidNotReceiveWithAnyArgs()`;
- `ReturnsForAnyArgs`;
- `WhenForAnyArgs`;
- `ReceivedWithAnyArgs`.

Ela nao reporta:

- `DidNotReceiveWithAnyArgs`;
- `Arg.Any<T>()` usado como argumento direto em verificacao negativa com `DidNotReceive()` ou `DidNotReceiveWithAnyArgs()`;
- metodos customizados com os mesmos nomes fora das APIs oficiais do NSubstitute;
- codigo fora de contexto de teste reconhecido.

## Opcoes publicas

Nao ha opcoes publicas especificas.

## Fallback de configuracao

Sem configuracao, a regra fica desabilitada. Ative com:

```ini
[*.cs]
dotnet_diagnostic.TST001.severity = info
```

## Limitacoes

A regra depende de reconhecimento semantico de NSubstitute e de contexto de teste. Ela nao oferece allowlist de metodos.

## Impacto esperado

Aumenta precisao de testes que usam substitutes, mantendo argumentos relevantes explicitos em setups e expectativas positivas.

## Suppression

Suprima quando a equipe aceitar matching amplo naquele teste especifico e a intencao estiver clara.

## Relacao com ferramentas externas

NSubstitute.Analyzers foca usos incorretos do framework. Esta regra cobre uma convencao de qualidade de teste: evitar APIs que tornam argumentos irrelevantes em setups e asserts positivos.
