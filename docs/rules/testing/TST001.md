# TST001: Restrict permissive NSubstitute argument matching

| Campo | Valor |
| ----- | ----- |
| Pacote | `CSF.Analyzers.Testing` |
| Categoria | TestQuality |
| Severidade | Info |
| Estado padrão | Opt-in |

## Objetivo

Evitar matchers e APIs excessivamente permissivas do NSubstitute quando elas reduzem a precisão do teste.

## Motivação

`Arg.Any<T>()` e as APIs `*AnyArgs` ignoram valores de argumentos. Em expectativas positivas e setups, isso pode esconder valores importantes e tornar o teste menos específico.

Verificações negativas amplas continuam aceitas quando a intenção é confirmar ausência de chamada independentemente dos argumentos.

## Código não conforme

```csharp
sender.Send(Arg.Any<string>());
sender.Received().Send(Arg.Any<string>());
sender.ReceivedWithAnyArgs().Send(default!);

formatter.Format("hello").ReturnsForAnyArgs("formatted");
sender.WhenForAnyArgs(x => x.Send(default!)).Do(_ => { });
```

## Código conforme

```csharp
sender.Send("hello");
sender.Received().Send("hello");

sender.DidNotReceive().Send(Arg.Any<string>());
sender.DidNotReceiveWithAnyArgs().Send(Arg.Any<string>());
sender.DidNotReceiveWithAnyArgs().Send(default!);
```

## Heurística

A regra só roda quando encontra contexto de teste reconhecido por atributos conhecidos e referência a `NSubstitute.Arg`.

Ela reporta semanticamente:

- `NSubstitute.Arg.Any<T>()` fora de argumento direto em cadeia `DidNotReceive()` ou `DidNotReceiveWithAnyArgs()`;
- `ReturnsForAnyArgs`;
- `WhenForAnyArgs`;
- `ReceivedWithAnyArgs`.

Ela não reporta:

- `DidNotReceiveWithAnyArgs`;
- `Arg.Any<T>()` usado como argumento direto em verificacao negativa com `DidNotReceive()` ou `DidNotReceiveWithAnyArgs()`;
- metodos customizados com os mesmos nomes fora das APIs oficiais do NSubstitute;
- código fora de contexto de teste reconhecido.

## Opções públicas

Não há opções públicas específicas.

## Fallback de configuração

Sem configuração, a regra fica desabilitada. Ative com:

```ini
[*.cs]
dotnet_diagnostic.TST001.severity = info
```

## Limitacoes

A regra depende de reconhecimento semântico de NSubstitute e de contexto de teste. Ela não oferece allowlist de métodos.

## Impacto esperado

Aumenta precisão de testes que usam substitutes, mantendo argumentos relevantes explícitos em setups e expectativas positivas.

## Suppression

Suprima quando a equipe aceitar matching amplo naquele teste específico e a intenção estiver clara.

## Relação com ferramentas externas

NSubstitute.Analyzers foca usos incorretos do framework. Esta regra cobre uma convenção de qualidade de teste: evitar APIs que tornam argumentos irrelevantes em setups e asserts positivos.
